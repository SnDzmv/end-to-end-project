# Неделя 12


## Цель

Реализовать инкрементальный ETL-пайплайн в Airflow с поддержкой:

- retry
- backfill
- idempotent load
- dq gate

---

# Архитектура DAG

```text
extract → transform → dq → load
```

Используется фиксированный `start_date`.

---

# Инкрементальность

Каждый DAG Run работает со своим периодом:

```python
{{ ds }}
```

Дата прокидывается в:

- mart.py
- dq.py
- load.py

---

# Артефакты

Файлы сохраняются с привязкой к периоду:

```text
data/mart/variant_13/mart_YYYY-MM-DD.csv
```


# Идемпотентность

Используется стратегия:

```text
DELETE period + INSERT
```

Перед вставкой выполняется:

```sql
DELETE FROM mart_yearly
WHERE run_date = :run_date
```

После удаления выполняется insert новых строк.

Повторный запуск того же периода не создает дубликаты.

---

# DQ Gate

DQ выполняется перед load.

При обнаружении FAIL:

```python
raise Exception("DQ FAILED")
```

Airflow помечает task как failed и останавливает DAG.

---

# Retry Safety

Retry безопасен, так как:

- используется delete+insert
- каждый run работает со своим периодом
- данные не дублируются

---

# Backfill

Backfill возможен без появления дублей.

Так как каждый период:

- обрабатывается отдельно
- перезаписывается атомарно
- не использует append без очистки
